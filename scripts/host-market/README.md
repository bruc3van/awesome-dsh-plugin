# DSH 发现页订阅索引

数据源仓库生成和验证索引，个人站点只分发固定 JSON：

- 订阅：`https://bruc3van.com/dsh-plugins/index.json`
- 旧地址（继续兼容）：`https://bruc3van.com/markets/dsh/index.json`；两个地址直接返回同一份 JSON，无重定向。
- 索引生成与排除报告：`https://bruc3van.com/markets/dsh/audit.json`
- 产物：`data/dsh-market-index.json`、`data/dsh-market-index.report.json`

`audit.json` 是保留兼容的旧地址。报告不是 DSH 官方审计认证，不代表安全审查或实机兼容验收。DSH 订阅读取 `index.json`，不消费此报告。

## 在 DSH 中启用并订阅

用户配置适用于 **DSH V0.2.1-rc.2 及以上**：

1. 打开左侧 **插件**，点击 **实验性插件** 旁的 **更多**，开启 **自定义插件市场**。
2. 进入 **发现**，首次使用时点击 **添加索引源**；已有市场时，从左上角市场下拉菜单打开 **管理索引源…**。
3. 在 **索引 URL** 中填入 `https://bruc3van.com/dsh-plugins/index.json`，点击 **添加**，确认其出现在列表后关闭弹窗。
4. 选择 **Bruce 的精选插件**，按需刷新、检索并安装插件。索引源保存在当前 profile 中。

[DSH 插件导航](https://bruc3van.com/dsh-plugins/) 用于网页浏览，不是要填写的 JSON 索引 URL。仅订阅官方「发现」页不需要安装 `safer-dsh-market`。完整用户说明见[仓库 README](../../README.md#订阅到-dsh-官方发现页)。

## 生成与来源

```sh
npm ci --ignore-scripts --prefix scripts/host-market
npm test --prefix scripts/host-market
node scripts/host-market/refresh.mjs
```

输入以社区 `data/market-v2.json`（含精选条目）为基础，并追加完整已批准目录中具备安装映射的仓库。候选先沿用审批、归档、禁用、黑名单及市场排除规则，再逐一核实 npm/Git 来源、bundle 和官方宿主兼容范围，并对安装包与 Git 来源中的仓库地址执行同一包级黑名单检查；`data/featured.json` 中的编辑推荐仓库本身豁免该包级检查——榜单排除针对 Star 数来源，不针对市场收录，人工精选即编辑决定，豁免以 `featured_repository_exempt` 诊断留痕。缺映射、手动安装、无效来源及同名冲突不会被转换或补造。全部合格条目按仓库 Star 数降序（同星按仓库名、插件名稳定排序）选取前 1000 个插件，不足 1000 时只发布实际通过核验的数量；`data/featured.json` 中已核验的编辑推荐条目会保留在这 1000 个名额内。报告 `candidateSelection` 记录候选来源与待核实数量，`selection` 记录合格总数、截断数及入选线 Star，`repositoryExclusions` 记录包级仓库排除；输入文件 SHA-256 用于追溯。社区 market-v2 文件不受影响。

输出使用固定 `@deepseek-ai/dsh-plugin-market-index@0.2.1-alpha.5` 校验。兼容范围复用官方 `dshRange`：优先使用显式 `engines.dsh`，否则求 DSH peerDependencies 范围交集；无约束时省略 engines，不填造 `*`。无效范围或空交集仍排除。

- **npm**：合并重复包名，按 feed 指定的版本或标签解析精确版本；核实 registry 名称、版本、发布时间和 bundle，下载对应 tarball 并校验完整性及实际 manifest，核实 bundle/宿主范围一致。展示信息来自最高收录版本的包文件。不是完整历史版本列表。
- **Git**：只处理 HTTPS 仓库，支持默认分支、明确分支/标签、完整 40 位 commit，以及 `&path:/目录`。引用解析到完整提交后，只从临时裸仓库读取对象；没有检出、安装、生命周期脚本、Git hooks、子模块或 LFS 下载。记录该提交的包 manifest SHA-256 和提交者时间。未指定子目录时按宿主规则发现根包、workspace 或有限深度的组合包。只收录所选提交中的版本，不把仓库历史自动扩展为安装目标。
- **冲突**：同名包优先 npm，其次按目录来源顺序取首个；不混合不同来源的同名包版本。报告标注被排除的重复来源。
- **不支持**：直接 tarball 安装地址、短 commit、无效 URL/目录分别给出明确原因。短 commit 不猜测补全。手动安装说明不转换。

图标最多内联 32 KiB。包内超过内联上限、但通过参考读取器大小检查的图标压缩为不超过 96px 的静态 WebP 后内联；报告记录输入输出摘要和字节数，无法转换时省略并给出警告，不使用猜测的头像或第三方图片。现有站点无需新增文件路由。底层文件读取组件来自固定宿主提交，许可证和文件摘要见 [vendor](vendor/README.md)。npm、Git 和核验工具均调用同一官方兼容范围解析器；无范围限制不代表已通过实机兼容验证。

## 编辑推荐数量

`data/featured.json` 维护 50 个推荐仓库，`expected_repository_count: 50` 指定推荐来源应有的仓库数。仓库与插件分别计数：宝玉设计对应三个插件；天枢 TUI 需手动安装、Univer Office 超出包体积上限，两项继续留在推荐来源中，但不会被伪造为订阅安装项。当前核验结果为 50 个可安装插件；一个仓库发布多个合格插件时，线上插件数可以超过 50。

生成、覆盖 data 和发布前校验都检查推荐来源的仓库数；与配置值不符时保留旧发布并报错，防止仅更新首页或部分数据却被报告为升级完成。生成报告的 `summary.featuredRepositories / featuredPlugins / expectedFeaturedRepositories` 分别记录来源仓库数、实际插件数和预期仓库数。数量要求不放宽安装来源、bundle、完整性和兼容范围的检查。

## 报告含义

`reportVersion: 2` 包含报告用途、宿主版本、feed/index SHA-256、npm registry 响应摘要、tarball 完整性证据、Git 提交及 manifest 摘要，以及分类型汇总。

每条诊断都有稳定的 `code`、`status`、`reason` 及可用的 target/name/version/path。`excluded` 是不符合本次收录条件；`unsupported` 是不支持该安装目标；`warning` 是展示字段等非致命问题；`error` 是来源读取失败；`info` 记录图标压缩和已审阅的展示补充。缺少兼容声明并不表示插件恶意，读取失败也不表示插件不兼容。

候选统计分别按去重 npm 包和 Git 目标计算；诊断可按版本或路径产生多条，不能把诊断条数当成独立插件数。使用 `indexSha256` 核对报告和索引是否属于同一代。

## 自动更新与失败处理

每日目录更新成功后，经 v2 工作流自动触发；映射、审批、排除规则及生成器变更也触发，并保留每日定时兜底。索引不足 1000 时，`expand-subscription-mappings.yml` 将已取证且身份可追溯的未映射仓库追加进 `data/packages.json`，并继续核验下一批高 Star 仓库；已有映射不改写，模板和身份不清的条目留给 `mapping-pending.md`。每日重新选取完整已批准且已映射候选，按 Star 排序取通过核验的前 1000 个插件，不为凑数降低核验标准。先生成 `.output/host-market/` 候选，校验数量、排序、报告哈希后才更新 data。来源读取失败、空索引、超过 1000 条或条目数低于旧索引的 80% 时不覆盖线上数据；失败候选保留为 Actions artifact 7 天。明确不存在或有歧义的引用作为排除记录，不伪装成网络错误。

索引和报告在同一 Git 提交中更新。只读任务安装依赖、取证及校验；独立发布任务只下载本次运行的数据产物，不安装依赖或执行产物。发布记录包含生成提交、触发提交、运行 ID 和两个文件的 SHA-256，main 与 market-release 以原子推送同步更新。主分支移动导致推送失败时保留旧发布，重新运行工作流以重新生成，不复用过期候选。社区 market-v2 生成及 npm 分发各有独立流程。网站部署凭据不进入公开仓库。

Cloudflare Pages Function 读取 `market-release` 指向的不可变发布记录，核对成功的生成任务、索引与报告摘要后分发 JSON，不重定向，也不接受自定义上游目标。当前发布读取失败时使用随网站部署的已校验备用快照，并通过 `X-Market-Fallback` 标注；显式指定版本不可用时返回 503，不替换为其他版本。成功发布的数据源更新无需重新构建个人站点。

## 仓库级分批核验

对 600 条主目录逐仓库检查（包括没有安装映射的条目），每批 200，结果可断点续跑。流程、覆盖边界与结果状态见 [分批核验说明](AUDIT.md)。这是映射修正前的取证步骤，不自动改写安装来源。

## 浏览、检索与筛选

使用 format-1 官方 `metadata.categories / labels / sortKeys` 声明和插件级对应字段：保留目录分类 id，并缩短部分中文分类名称；`data/featured.json` 中的条目单独归入「编辑推荐」分类，同时保留原分类同义词便于搜索。标签包括实际发行来源 npm/Git、已审阅的少量功能标签，以及由 `pushed_at` / Star 计算的更新时间和热度档位。更新时间显示近7天或近30天；Star 使用 50+、100+、500+、1k+、5k+、10k+ 短标签，只显示达到的最高一档，低于50星不显示。每个插件最多显示一个更新时间标签和一个 Star 档位标签；Star 未知或低于50、更新时间无效或距今已满30天时，省略对应标签。用途与使用方式标签由 `value-labels.mjs` 统一定义，在 `presentation.json` 中逐包审阅分配；维度涵盖用途、工作方式、使用入口和明确的使用前提（如需 API Key、需浏览器扩展）。每个插件最多三个此类标签，不从类别、包名或关键词自动猜测，不标注未经证实的免费、离线或安全保证。标签复用展示指纹校验；上游展示字段改变时先省略并等待复核。维度用于维护，官方 format-1 界面仍展示为平铺标签。保留包 keywords，补充映射的 tasks、分类同义词和已核实的中英文功能词。官方搜索也会索引分类、标签的各语言名称。标签多选为 AND，不是并集。

`presentation.json` 单独维护包级展示翻译和摘要，记录已审阅版本、原始标题/描述/repository 的 SHA-256 及来源；上游这些展示字段变化时跳过覆盖并报告待复核，原有其他语言文本保留。它只补充展示字段、用途标签和检索词，不更改包名、安装来源、版本、兼容范围、作者或主页。当前版本基准为 `0.2.1-rc.2`，`0.2.1` 只是项目交流中的简写，不表示另一个正式发布版本。

报告的 `presentationQuality` 记录图标、包名标题、中文描述/关键词、缺失链接及对 `0.2.1-rc.2` 的声明兼容性覆盖。生成/校验器的固定 alpha.5 基线与客户端版本分别记录，不能把这些统计解读为实机兼容验收，也不会为了提高覆盖率填造作者或放宽版本范围。

默认仍按 Star 降序，用户还可以选择「GitHub Star 数」「仓库更新时间」并切换升降序。仓库更新时间来自 snapshot 的 pushed_at，不冒充插件发布时间；发布时间与搜索最佳匹配由宿主原生提供。元数据只使用实际来源所属仓库，缺失时间不填假值。旧宿主是否展示取决于其发现页功能；已用固定 alpha.5 官方 schema 验证。
